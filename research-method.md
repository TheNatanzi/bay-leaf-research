# Venue research — follow the evidence

- **Page → links → documents → dated facts → visible columns.** Downloaded is not reviewed; reviewed is not necessarily normalized.
- Check the official venue page, its menus, FAQ, pricing, brochures, contracts, attachments and linked event pages. Follow generic “View now” buttons, embeds and pagination; keep a disposition for each resource.
- Read the document’s actual date and pricing basis. A URL year, filename, copyright or crawl date is not the effective date.
- Match the parent property, exact room/package, layout, guest basis, weekday, season and rental duration. Never add overlapping rooms or turn ceremony/standing capacity into dinner capacity.
- Separate event, indoor/outdoor music, bar, departure and cleanup clocks. Office hours, rental windows and durations do not prove a music cutoff.
- Capture mandatory lodging, room-night liability, staffing, catering buyouts, cleaning, taxes, service charges and percentage bases. Refundable deposits are cash exposure, not automatically expenses. Unknown mandatory charges prevent an all-in price.
- Preserve old values and source dates. Flag contradictory current sources; newer-looking filenames alone cannot resolve them. Mark researched unanswered fields separately from unsearched fields.
- Inspect an alternate route when a high-impact answer is missing: current operator links, a targeted standard web search, ordinary browser navigation or a directly linked download. Record blocked/unreadable routes; do not bypass restrictions.
- **Firecrawl is last resort:** use existing archives, ordinary web tools, direct downloads and browser methods first. Bound any necessary call; do not use it to bypass access restrictions or purchase credits.
- Rebuild the numeric layer, check provenance and compare before/after. Test critical costs, clock rollover and conflicts; verify the published page and archive sources permanently.

## Completion labels

| Label | Meaning |
|---|---|
| Captured | Bytes/links saved; content may be unread |
| Reviewed | Specific pages/sections inspected |
| Applied | Supported facts entered and linked to evidence |
| Verified | Numeric/UI checks passed |
| Unknown — inquire | Reviewed sources did not settle this field |
| Unsearched | No documented attempt for this field |

A scoped audit can finish while questions remain. It does not establish exhaustive discovery or that every possible method was exhausted.

## Discovery gates — reviewed November 8, 2026

- Search independent source families: official tourism, venue associations, caterer/planner partners, wedding directories, government authorities, and unconventional operators. Test each county; a popular regional list is not a county inventory.
- Every captured lead retains a dated disposition and stable identity reference. A name match suggests a review; it does not automatically finish it. Keep property identity, wedding eligibility, date availability and missing-field review separate.
- Read the requested property body and final URL. A redirect to a roster, JavaScript shell, form gate or successful HTTP response without content is not a completed property review.
- Compare exact address, operator and jurisdiction. Resolve city namesakes, rebrands, room combinations, mobile vessels and boarding ports without fuzzy automatic merges.
- Treat source labels and badges as claims. Verify operator facts; record approximate counts, lower bounds, layout conflicts and source-effective dates. An expired deadline on a live page is not an active lease opportunity.
- Canonicalize fragment-only profile links; exclude skip/navigation targets. Explicit roster collection must inspect the actual member list even when it sits in navigation; the document extractor’s navigation filter is not an inventory-completeness check.
- Use an independent holdout roster after a search batch. Record omissions, duplicates, exclusions, blocked routes and unresolved profiles, then improve the next search. Twenty loops are evidence of twenty scoped reviews, not all venues found.
- Research takes priority over interface changes until the outstanding research is completed or a concrete evidence/access dependency remains.
## Download checks

- Follow the current page’s brochure, rate-sheet and policy links; do not rely only on search results or an old saved URL.
- Check downloaded bytes against the response length or size limit. A truncated file is a failed capture.
- Verify the PDF opens and has pages. No extracted text may mean an image-only PDF: inspect the actual page before copying table values.
- Record internal effective dates separately from filenames and fetch dates. Historical prices stay historical.
- Keep failed captures and their corrected outcomes in the audit; preserve the full replacement separately.


## Alternate-route checks added November 8, 2026

- Follow named facility/room profiles and accessible button labels, including linked publication viewers. Keep each route pending until its content is actually reviewed.
- Check the authority’s finance/adopted-fee index when a venue page links an older brochure. Search engines may substitute older schedules for an exact current-file query; verify the opened source’s internal date.
- A failed browser download does not prove the document is unavailable. Try its already-published direct URL using an ordinary download when permitted. Respect robots and access blocks; never use another tool to bypass them.
- For a PDF marked reviewed, account for every actual page number. Inspect image-only/table pages visually. A pair of arbitrary page numbers is not a complete two-page review.
- Preserve disagreements, such as two parking prices on the same current page. Avoid one numeric fee until its applicable basis is resolved. Descriptive mansion rooms are not lodging bedrooms.
